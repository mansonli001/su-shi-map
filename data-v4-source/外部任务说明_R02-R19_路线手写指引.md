## 零、项目核心简介（⭐⭐⭐ 外部协作者必读）

### 0.1 这是什么项目？

**苏轼行踪地图（Su Shi Map）** —— 一个交互式 Web 地图应用，用可视化方式展示苏轼一生（1037–1101）的全部行踪轨迹。

用户（mansonlee）想做一件事：
> 把苏轼一生到过的所有地方，做成一幅可以交互的地图，让更多人直观理解"苏东坡的漂泊一生"。

### 0.2 为什么需要手写（而不是 AI 生成）？

**核心原因：AI 会编造，苏轼研究容不得半点虚构。**

- 苏轼研究有两位权威：
  - **李常生《苏轼行踪考》**（上下册，考据极详）
  - **孔凡礼《苏轼年谱》**（中华书局，编年精准）
- AI 生成路线时，容易"合理推测"—— 比如"苏轼可能路过这里"—— 但地图是严肃的文化产品，**每个点都必须有史料支撑**
- 所以：**路线框架 + 点位选择 + 事迹描述** 必须人工手写，AI 只负责后续的坐标拾取和格式转换

## 一、核心规则（⭐ 必读）

### 1. 点位数量：**不限**

**以完整覆盖苏轼在该路线的全部行踪为准——宁多勿漏**

- ❌ **删除旧规则**："每条路线 6-12 个点"（已废止）
- ✅ **新规则**：苏轼实际到过的地方有多少写多少，强行截断会丢信息
- 分层原则不变：`main`（主线必经）+ `water`（沿途水景）+ `surrounding`（驻留周边）三层结构

### 2. 史实准确性（最高优先级）

| 要求 | 说明 |
|---|---|
| **不会的字段空着** | 不要编——编了 AI 考证不出来，比空着还糟 |
| **时间不确定** | 写"约 XXXX 年"，AI 会去查李常生《苏轼行踪考》+ 孔凡礼《苏轼年谱》交叉验证 |
| **民间传说标注** | "唤鱼池题名"这类传说，标注 `（传）` 或 `（民间相传）`，不与正史混 |
| **地点今址不确定** | `name_modern` 写"待考"或留空，不要瞎编 |

### 3. 「苏轼关联事迹」是地图的灵魂

- **每个点都必须写 `su_shi_story`**，不能只写"苏轼曾在此停留"
- 这是用户在地图上点开标记后看到的核心内容，要有画面感、有情感、有历史细节



### 3.3 整体核心评述（150-300 字）⭐⭐⭐ 路线层的灵魂

> **这是路线层的灵魂**，决定用户在地图首页看到这条路线时，第一眼能不能被吸引住。
> **外部协作者最容易写砸的部分**：写成流水账 / 写成景点介绍 / 写得太短（<100 字）。

#### ✅ 好的核心评述长什么样？

**标准**：有判断、有情感、有历史定位，不是"苏轼去了哪里"而是"这条路线在苏轼一生中意味着什么"。

**好例子（R00 眉山故里）**：
```yaml
core_essence: |
  眉山是苏轼精神原乡，少年经历塑造其一生人格底色：
  母亲程夫人"范滂传"启蒙奠定其刚直气节，
  父亲苏洵发奋苦读成为其治学榜样，
  青神中岩寺"唤鱼联姻"王弗奠定其情感底色。
  这条路线不是"出生地"那么简单，
  而是理解"苏轼为什么会成为苏轼"的第一把钥匙。
```
→ 点评：有判断（精神原乡、人格底色）、有情感（范滂传、唤鱼联姻）、有历史定位（理解苏轼的第一把钥匙）

**好例子（R01 首次进京）**：
```yaml
core_essence: |
  这条路线是苏轼从"蜀中天才少年"到"全国知名的进士"的跃迁之路。
  出蜀时意气风发，母丧返程时悲痛欲绝，
  两段极端情绪在同一路线上交织，
  预示其一生"高光与至暗交替"的命运模式。
  进京赶考遇见欧阳修，是其文坛地位的起点；
  母丧丁忧返蜀，是其"孝"与"仕"拉扯的首度演练。
```
→ 点评：有判断（跃迁之路、命运模式）、有情感（意气风发/悲痛欲绝）、有历史定位（文坛起点、孝仕拉扯）

#### ❌ 坏例子（别这样写）

**坏例子 1：写成流水账**
```yaml
core_essence: |
  苏轼从眉山出发，经过成都、剑门关、长安，到达汴京。
  在汴京参加科举考试，中了进士。
  后来母亲去世，苏轼返回眉山守丧。
```
→ 问题：只是"去了哪里"，没有"意味着什么"。用户看完不知道这条路线为什么重要。

**坏例子 2：写成景点介绍**
```yaml
core_essence: |
  这条路线经过成都、剑门关等著名景点。
  剑门关地势险要，有"一夫当关万夫莫开"之称。
  汴京是北宋都城，繁华无比。
```
→ 问题：这是在写旅游攻略，不是在写苏轼的人生。

**坏例子 3：写得太短（<100 字）**
```yaml
core_essence: |
  苏轼首次进京赶考，中了进士，后来母丧返蜀。
```
→ 问题：150 字是最低要求，太短说不清楚"这条路线意味着什么"。

#### 📝 写作 Checklist（写完对照）

- [ ] **有判断**：明确说了"这条路线在苏轼一生中是什么角色"（不能只说"苏轼去了哪里"）
- [ ] **有情感**：写到苏轼的情绪变化（兴奋/悲痛/孤独/豁达……），不是冷冰冰的编年史
- [ ] **有历史定位**：说清楚这条路线和苏轼其他路线相比，独特价值在哪里
- [ ] **150-300 字**：太短说不清楚，太长用户不想看
- [ ] **不说废话**：不要写"苏轼是北宋著名文学家"这种百度百科式废话

#### 📐 推荐结构（照着套）

```
第一句：这条路线在苏轼一生中是什么角色（判断句）
第二句：这条路线的情感基调是什么（苏轼的情绪变化）
第三句：这条路线和苏轼其他路线相比，独特价值在哪里（历史定位）
第四句：这条路线埋下了苏轼后期什么伏笔（可选，加分项）
```

**示例（按推荐结构套）**：
```
这条路线是苏轼从"蜀中天才少年"到"全国知名进士"的跃迁之路。【判断】
出蜀时意气风发，母丧返程时悲痛欲绝，两段极端情绪交织。【情感】
遇见欧阳修是其文坛地位起点，母丧丁忧是其"孝仕拉扯"首度演练。【定位】
"高光与至暗交替"的命运模式，在这条路线上首次显现。【伏笔，加分】
```

## 四、点位层字段说明（`places[]`）

> **每个点位** 按下面 **14 个字段** 填写（参照 R00 样板）

### 4.1 三层分类说明

| layer | 视觉 | 选什么进来 |
|---|---|---|
| `main` 主线 | 地图大墨点（实心，路线主题色） | 苏轼**必去**的核心点位（住过/任职过/重大事件发生地） |
| `water` 水景 | 中墨点（青色描边） | 沿途江河湖渡口（写过诗 / 反复经过 / 有名意象） |
| `surrounding` 周边 | 小墨点（灰色虚框） | 驻地辐射的访友 / 访寺 / 访道点（短暂停留但有事迹） |

**原则**：一条路线 `main` ≥ `water` ≥ `surrounding` 的数量（大致比例，非硬性）

### 4.2 单点位完整字段（14 个）

> **下面用 R00 的「眉山故居」作示例**，所有点位格式一致

```yaml
- id: R02_HZ_something          # {路线id}_{地区两位拼音}_{地点拼音}
  #   地区码：BO=眉山 / HZ=杭州 / HU=黄州 / DA=惠州 / DAN=儋州 等
  #   ⚠️ id 必须全局唯一，不能与其他路线重复

  name_song: 宋代名（苏轼当时的称呼）
  name_modern: 现代行政区划地名（精确到街道/镇/村）

  layer: main                    # main / water / surrounding
  tags: [official, stay, poetry]  # 复合标签，见下方标签库

  priority: P0                   # P0 必上 / P1 建议上 / P2 可选
  # ↑ 如果地图最终只显示 5 个点，P0 一定要留，P2 第一个砍

  order_in_route: 1              # 在本条路线的时序位置（数字越小越早）

  # ========== 时间维度 ==========
  duration: 1071-1074 年任杭州通判，驻留三年
  duration_years: [1071, 1074]  # 数值化，时间轴动画用
  # 如果是短暂停留：duration_years: [1080, 1080]，duration: "约一月"

  # ========== 内容三栏（地图灵魂） ==========
  historical_context: |
    地点本身的历史背景，与苏轼无关也要写——给地点定调用。
    例：西湖为杭州核心湖泊，唐代已为名胜，
    北宋时为士民游赏胜地，苏轼任通判期间主持疏浚工程。

  su_shi_story: |
    ⭐⭐⭐ 这一栏是地图的灵魂，必须详细写
    苏轼在此发生了什么——任职 / 写诗 / 见谁 / 内心活动。
    例：苏轼任杭州通判期间，常夜游西湖，
    留下"欲把西湖比西子，淡妆浓抹总相宜"千古名句。
    此地是其山水诗风成熟的关键场域，亦为后世"苏堤"文化记忆的最早源头。

  essence: 杭州任上核心政绩与诗文创作地
  # ↑ 一句话定位，PlaceCard 标题副栏用

  # ========== 关联诗文（有就填，没有就空数组） ==========
  related_works:
    - title: 饮湖上初晴后雨
      type: poem                # poem 诗 / ci 词 / fu 赋 / wen 文
      excerpt: "欲把西湖比西子，淡妆浓抹总相宜"
      note: 西湖题材代表作

    - title: 孤山灵隐寺题咏
      type: poem
      excerpt: null
      note: 游寺访僧所作

  # ========== AI 自动填，你不用管 ==========
  coordinates: null             # [lng, lat] AI 后续用高德 API 拾取
  images: []                    # 本地 data/ 图片映射，下一轮做
  verified: false               # AI 考证后改 true
  sources:                      # 来源记录
    - 用户手写归纳
```

### 4.3 标签库 `tags[]`（复合多选）

| `exile` | 贬谪 | 黄州、惠州、儋州 |
| `visit` | 短暂游览 | 蟆颐山、青神 |
| `friend` | 访友 / 见挚友 | 见王巩、见佛印、见黄庭坚 |
| `poetry` | 重要诗词诞生地 | 赤壁、惠州西湖 |
| `main` | 路线主线节点 | （和 layer:main 配套） |
| `hub` | 水陆枢纽 / 中转 | 彭山江口、瓜洲渡 |

**复合用法**：
- 眉山故居 = `[birth, stay, study]`
- 黄州赤壁 = `[exile, poetry, visit]`
- 徐州 = `[official, stay]`

## 五、路线最终核验总结（每条路线末尾必写）⭐⭐⭐

> **这是外部协作者最容易漏写/写不好的部分**。
> **为什么重要？** → AI 入库脚本会读这个总结，判断这条路线"是否史实可靠"。
> 写得好 = AI 放心入库；写得差 = AI 标记为 `verified: false` 人工复审。

### 5.1 好总结 vs 坏总结

#### ✅ 好总结长什么样？

**标准**：
1. **关键时间节点列清楚了**（不是"苏轼去了很多地方"，而是"1037 年出生、1054 年娶王弗、1056 年离蜀"）
2. **史料依据点名了**（李常生《苏轼行踪考》+ 孔凡礼《苏轼年谱》）
3. **点位数量说明了**（main N1 + water N2 + surrounding N3，总共 N 个）
4. **分层逻辑说清楚了**（为什么分这三层、每层是什么意思）
5. **民间传说标注了**（如果有，明确说"已标注'传'"；如果没有，写"无民间传说"）
6. **不写"略超上限"**（点位不限，不要提旧规则）

**好例子（R00 眉山故里）**：
```markdown
---

## 路线最终核验总结

本条 R00 路线全程史实严格依据 **李常生《苏轼行踪考》** 核心记载与 **孔凡礼《苏轼年谱》** 少年部分交叉印证：
1037 年苏轼出生于眉山纱縠行故宅、1054 年于青神迎娶王弗、
1056 年正月辞蜀北上赴京，
时序精准、事件无杜撰。
全文点位共 13 个（main 7 个 + water 3 个 + surrounding 3 个），
以覆盖苏轼少年期全部行踪轨迹为准，不强行截断，
分层清晰、所有事迹与时间均有权威史料支撑，
民间传说（如"唤鱼池"题名）已显式标注"传"或"民间相传"以示区分，
无虚构内容，完全适配 JSON 数据库入库标准。

> （注：文档部分内容可能由 AI 生成；少年期具体年份多为约数，AI 入库时将依据《苏轼年谱》逐条核验补全。）
```

→ 点评：
- ✅ 关键时间节点列清楚（1037/1054/1056）
- ✅ 史料依据点名（李常生 + 孔凡礼）
- ✅ 点位数量说明（13 = 7+3+3）
- ✅ 分层逻辑说清楚（"以覆盖全部行踪为准，不强行截断"）
- ✅ 民间传说标注（"唤鱼池"传）
- ✅ 不写"略超上限"

#### ❌ 坏总结长什么样？

**坏例子 1：太简略（AI 无法判断可靠性）**
```markdown
本条路线依据李常生《苏轼行踪考》，
点位共 8 个，无虚构内容。
```
→ 问题：
- ❌ 关键时间节点没列（哪一年？）
- ❌ 点位数量没说明（8 = 几个 main？几个 water？）
- ❌ 民间传说没提（有没有？标注了吗？）
- ❌ AI 看完不知道该不该入库

**坏例子 2：写"略超上限"（旧规则残留）**
```markdown
全文点位共 15 个，略超模板 6-12 上限但保留完整轨迹……
```
→ 问题：
- ❌ "略超上限"是旧规则，已经废止了
- ❌ 外部协作者可能照抄，导致总结不一致

**坏例子 3：史料依据不明确**
```markdown
本条路线依据相关资料，时序精准。
```
→ 问题：
- ❌ "相关资料"太模糊，必须点名"李常生《苏轼行踪考》+ 孔凡礼《苏轼年谱》"
- ❌ AI 入库时要核对依据，写不清楚会增加人工成本

### 5.4 常见问题

**Q1：如果这条路线没有民间传说，总结怎么写？**
A：直接写 `无民间传说`，不要留空或不提。例：
```markdown
无民间传说，所有事迹均有权威史料支撑。
```

**Q2：关键时间节点要列多少个？**
A：3-5 个，按时间顺序排列。不要只列 1-2 个（太简略），也不要列 10 个（太啰嗦）。

**Q3：如果这条路线的时间跨度很大（如 10 年），关键时间节点怎么选？**
A：选**最重要的 3-5 个节点**（出发/到达/重大事件/离开），不要试图列每年。

**Q4：总结要写在文件的哪个位置？**
A：**每条路线的 `.md` 文件末尾**，在 `---` 分隔线之后，用 `## 路线最终核验总结` 二级标题。

**Q5：总结写错了，AI 入库时会怎么样？**
A：AI 会标记为 `verified: false`，并让你人工复审。写对了 = 直接入库，省时间。

## 九、常见问题 FAQ

### Q1：一条路线写多少点位合适？

**A**：有多少写多少，不限制。如果某条路线苏轼确实只去了 3-4 个地方，那就写 3-4 个；如果去了 20 多个地方，那就写 20 多个。**宁多勿漏**。

### Q2：`priority` 怎么打？

**A**：
- **P0**：这条路线最核心、绝不能漏的点（通常 main 层 60-70% 的点）
- **P1**：重要但不绝对核心的点（通常 main 层 30-40% 的点 + water 层大部分点）
- **P2**：辅助性的点（通常 surrounding 层大部分点 + water 层少数点）

### Q3：`order_in_route` 怎么排？

**A**：按苏轼在该路线的**行进时序**排，不是按重要性排。
- 出蜀路线：眉山（1）→ 成都（2）→ 剑门关（3）→ …
- 贬谪路线：汴京（1）→ 黄州（2）→ …

### Q4：苏轼到过某个地方，但史料记载很简略，`su_shi_story` 写不出很多怎么办？

**A**：写多少是多少，不要编。**宁可简略也不要虚构**。
- 可以写：`苏轼于此地短暂停留，史料记载简略，待进一步考证。`
- 不可以写：`苏轼于此地与友人把酒言欢，畅谈天下大势……`（完全编造）

### Q5：`coordinates` 字段我需要填吗？

**A**：**不需要**。这个字段 AI 会用高德 API 自动拾取，你只管写 `name_modern`（现代地名）就行。
